# Unfold Agent Context

## Project overview

Unfold is a single-page, vanilla HTML/CSS/JavaScript personal-growth app. It combines CBT check-ins, guided journaling, breathwork, rituals, affirmations, mood trends, reflections, themes, and Supabase email/password authentication.

The app is in `openCircle_registration/unfolddd/` and is served as a Vite project. There is no framework, TypeScript, test suite, or lint configuration.

## Important files

- `index.html`: The complete UI shell. Contains the auth overlay, desktop sidebar, mobile navigation, and seven page sections: home, check-in, journal, breathwork, ritual, affirmations, trends, and settings.
- `app.js`: Nearly all application behavior and static content. It initializes on `DOMContentLoaded`, wires event handlers, switches page sections, manages local state, renders UI, and handles authentication/journal Supabase calls.
- `style.css`: All layout, responsive behavior, six theme palettes, animations, and component styles. Theme selection is driven by `body[data-theme]`.
- `supabase.js`: Creates and exports the Supabase client and exports `getCurrentUser()`.
- `cloud-sync.js`: Empty placeholder. It is not imported or used.
- `vite.config.js`: Vite dev server uses port `5173`, opens the browser, and writes builds to `dist/` with sourcemaps.
- `README.md`: Product description and setup notes; some claims are stale relative to the current implementation.

## Run and validate

From this directory:

```bash
npm install
npm run dev
npm run build
npm run preview
```

`npm run build` currently cannot run until `npm install` has populated `node_modules`. There are no automated tests or lint scripts; validate behavior manually in a browser after starting Vite.

## Runtime architecture

1. `app.js` imports `supabase` and `getCurrentUser` from `supabase.js`.
2. On `DOMContentLoaded`, it sets up auth listeners, checks the Supabase session, initializes date/quote/navigation/theme/home/check-in/journal/breathwork/ritual/affirmations/trends/settings/mobile menu/reflection.
3. Navigation is client-side: `navigateTo(page)` hides all `.page` sections, activates `#page-${page}`, updates nav active states, closes the mobile sidebar, and refreshes home/trends/settings where needed.
4. Most data is local and rendered immediately from `localStorage`; keys are prefixed with `mindroot_` by the `save()` and `load()` helpers.
5. Supabase is used for auth and journal entries. Journal drafts remain local, but saved journal entries require a signed-in user and are read/written from the `journal_entries` table.
6. Inline `onclick` handlers generated by `app.js` require these functions on `window`: `toggleStep`, `deleteStep`, `unsaveAffirmation`, `selectTheme`, and `loadEntry`.

## Persistence contract

The local storage helper maps `save('x', value)` to `mindroot_x`. Current keys include:

- `mindroot_theme`
- `mindroot_checkins`
- `mindroot_journalDraft`
- `mindroot_ritualSteps`
- `mindroot_savedAffirmations`
- `mindroot_dailyReflection`
- `mindroot_reflectionWriting_<YYYY-MM-DD>`

Check-ins are appended with date, timestamp, mood (1-5), mood emoji/label, energy (1-10), and distortion ids. Streaks and trends are derived from check-ins. Ritual steps and saved affirmations are local-only. The reflection prompt/history and daily writing are local-only.

`todayKey()` uses `new Date().toISOString().split('T')[0]`, so dates are UTC rather than the user's local calendar date. Keep this in mind when changing daily behavior.

## Supabase contract

`supabase.js` currently contains a project URL and public anon key and enables persisted sessions, token refresh, and URL session detection. The anon key is client-side by design, but database Row Level Security must protect user data.

The app expects a `journal_entries` table with at least:

- `id`
- `user_id`
- `date`
- `text`
- `prompt`
- `prompt_source`
- `created_at`

Queries filter journal entries by the authenticated `user.id`. `saveJournalEntry()` inserts and selects one row; `renderEntries()` selects the latest 10 by `created_at`; `loadEntry(id)` filters by both entry id and user id.

Auth behavior:

- The auth overlay is shown when there is no Supabase session.
- The app initializes all feature UI regardless, but the overlay blocks access until sign-in/sign-up succeeds.
- Sign-in uses `signInWithPassword`; sign-up uses `signUp`; sign-out uses `signOut`.
- `onAuthStateChange` updates the overlay and account displays.
- Journal save/list/load requires authentication. The intended unauthenticated local journal fallback is documented in comments but is not used by those journal functions.

## Known caveats for future work

- README says the app is offline-first and can be opened directly, but the current module imports `@supabase/supabase-js`; direct opening of `index.html` is not a reliable way to run the current code. Use Vite after `npm install`.
- README says cloud sync is optional, while the current startup flow requires Supabase session/auth UI and journal persistence requires Supabase. Reconcile product behavior and documentation before changing auth.
- `cloud-sync.js` is empty and there is no general synchronization of local check-ins, ritual data, affirmations, themes, or reflections to Supabase.
- `analyzeUserContext()` performs a Supabase journal query during dashboard greeting generation when authenticated, which makes home refresh asynchronous and dependent on network availability.
- There are many diagnostic `console.log` calls in journal/auth paths; preserve or remove deliberately when debugging is complete.
- Several rendered HTML fragments use interpolated values inside `innerHTML` and inline handlers. Escape user-controlled text or move to DOM APIs if changing rendering/security-sensitive paths.
- Date calculations mix UTC date strings and local `Date` parsing. Avoid introducing new date assumptions without deciding whether daily data is local-time or UTC.
- Canvas chart colors only explicitly distinguish the `dark` theme; other themes use light-theme chart colors.

## Editing guidance

Prefer small, local changes that match the existing vanilla JS style. Keep new page controls in `index.html`, behavior in `app.js`, and visual changes in `style.css`. If adding persisted state, use `save()`/`load()` so the `mindroot_` namespace remains consistent. After edits, run `npm run build` and manually exercise the affected page in the browser; install dependencies first if needed.
